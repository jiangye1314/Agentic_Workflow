## 1. 背景与目标

### 1.1 痛点

1. **批改耗时**：一名初中数学教师每天批改 2 个班约 100 份作业，客观题批改约 40 分钟，主观题批改约 2 小时，挤占备课与教研时间。
2. **主观题标准不一**：同一道解答题，不同教师给分差异可达 8–10 分（百分制），家长质疑时缺乏统一口径。
3. **学情数据分散**：错题散落在纸质作业本里，无法按知识点归因，教师讲评只能"凭感觉"挑重点。

### 1.2 目标（量化）

| 编号 | 指标 | 现状基线 | 目标值 | 衡量方式 |
| --- | --- | --- | --- | --- |
| G-01 | 单班单次作业批改耗时 | 约 2.5 小时/班 | ≤ 1 小时/班 | 批改任务起止时间戳统计 |
| G-02 | 主观题评分一致性 | 教师间偏差 8–10 分 | AI 与教师偏差 ≤ 5 分（百分制） | 双评对照抽检 |
| G-03 | 错题知识点归因覆盖率 | 0（无系统） | 100% 作业覆盖 | 每份批改结果必含知识点标签 |
| G-04 | 低置信度转人工率 | — | 15%–25% | 置信度 < 0.7 的批改占比 |
| G-05 | 教师对 AI 批改的改判率 | — | 首月 ≤ 30%，三月后 ≤ 15% | 人工复核队列改判统计 |

### 1.3 平台定位

面向中学的校内教学平台：**确定性规则负责判分与统计，AI 负责主观评判与归因，人工复核兜底**。一期聚焦"作业批改闭环"，二期扩展教研与家校方向。

### 2.1 角色定义

| 角色 | 职责 | 关键操作 |

| 教研组长 | 把控批改质量、制定评分标准 | 质检中心、评分 rubric 库、抽检 |

| 系统管理员 | 平台配置、AI 网关管理 | 网关管理、阈值配置、日志审计 |

| 功能 | 教师 | 学生 | 教研组长 | 教务 | 系统管理员 |

### 2.3 核心场景

1. **日常作业批改闭环**（主场景，P0）：教师布置 → 学生提交 → 系统自动批改（客观题规则引擎 + 主观题 AI）→ 低置信度进人工复核 → 教师确认发布 → 错题入错题本 → 学情画像更新。
2. **期中测评统一批改**：教研组长配置评分 rubric，全年级统一口径，AI 批改后按 10% 比例抽检人工双评，比对偏差。
3. **教研复盘**：教研组长在质检中心查看各教师改判率、AI 评分偏差分布，迭代 rubric 库。

## 4. 业务规则（含数值边界）

| 编号 | 规则 | 内容 | 数值/边界 |
| --- | --- | --- | --- |
| R-01 | 客观题判分 | 选择题/判断题/填空题由规则引擎比对答案，不走 LLM；结果即时返回 | 判分耗时 < 1s/份 |
| R-02 | 主观题 rubric 化 | 每道主观题必须绑定评分标准（分档描述 + 满分值），LLM 按 rubric 逐点打分并给出评语 | 无 rubric 不允许发起 AI 批改 |
| R-03 | 置信度分层 | LLM 批改返回 score + confidence + reasoning；confidence < 0.7 自动进入人工复核队列 | 阈值 0.7，可在质检中心调整（0.5–0.9） |
| R-04 | 数学题双通道 | 最终答案用 sympy 符号验证（确定性）；解题步骤由 LLM 评判逻辑；答案错误时步骤分上限 40% | 答案分 : 步骤分 = 4 : 6（可配） |
| R-05 | 作文四维评分 | 立意/结构/语言/卷面四维打分 + 修改建议 + 范文片段对照；总分按权重合成 | 权重默认 3:3:3:1 |
| R-06 | 改判回流 | 教师改判的记录（原 AI 评分 + 改判评分 + 理由）自动进入 few-shot 示例库，用于后续同类型题目 prompt | 示例库按题型分桶，每桶上限 20 条，先进先出 |
| R-07 | 分数申诉 | 学生可对已发布分数申诉，教师/教研组长复核后改判；申诉与改判全程留痕 | 单份作业限申诉 1 次 |
| R-08 | 质检抽检 | 教研组长对已批改作业按比例抽检，人工双评，偏差超阈值触发 alert | 默认抽检 10%，偏差阈值 5 分 |
| R-09 | 批改留痕 | 每条批改结果记录：批改者（AI/人工）、模型版本、置信度、改判历史 | 不可物理删除，仅可标注"作废" |
| R-10 | 网关降级 | agent-gateway 不可用或超时，批改任务进入待处理队列并提示；提供 mock 批改兜底（标注"演示数据"） | 超时 30s，重试 2 次 |

### 5.2 学校风格视觉规范

| 项 | 规范 |
| --- | --- |
| 主题 | 浅色（强制）：背景 #f6f8fa，卡片 #ffffff，边框 #dfe3e8 |

| 标签 | 菜单项右侧小标签（核心/合规/AI/RAG 等），等宽字体 + 浅色底 |

### 5.3 关键路径：作业批改闭环

1. 教师【作业布置】：选班级 → 组卷/导入题目 → 为每道主观题填 rubric → 发布，截止时间写定。
2. 学生【提交】：作答并提交；客观题**即时**返回判分，主观题显示"AI 批改中"。
3. 系统【AI 批改】：客观题规则引擎 → 主观题 LLM（rubric 化 prompt + 数学 sympy 校验）→ 写入批改结果。
4. 分流：confidence ≥ 0.7 直接待发布；< 0.7 进入【人工复核队列】。
5. 教师【复核】：改判或确认；改判记录回流 few-shot 库。
6. 发布 → 学生查看分数/评语/错题 → 错题按知识点入【错题本】→ 学情画像更新。
7. 教研组长【质检中心】抽检 10%，偏差超阈值触发整改提示。

## 7. 验收标准（Given / When / Then）

| 编号 | 验收标准 |
| --- | --- |
| AC-01 | Given 教师发布含 10 道客观题作业 When 学生提交 Then 系统 1 秒内返回判分，正确率与手算一致 |
| AC-02 | Given 主观题已绑定 rubric When 发起 AI 批改 Then 返回分数、分点评语、confidence、reasoning 四要素 |
| AC-03 | Given AI 批改 confidence 为 0.55 When 批改完成 Then 该任务出现在人工复核队列，且不出现在"待发布"列表 |
| AC-04 | Given 教师改判某题分数并填写理由 When 保存 Then 改判记录（AI 原分/改判分/理由）写入 few-shot 示例库且批改历史可见 |
| AC-05 | Given 数学题学生最终答案错误、步骤部分正确 When AI 批改 Then 答案分 0 分、步骤分按 rubric 给分且 ≤ 满分的 40% |
| AC-06 | Given 学生提交申诉 When 教师复核后改判 Then 分数更新且申诉与改判全程留痕，学生端可见处理状态 |
| AC-07 | Given 教研组长抽检 20 份 AI 批改 When 双评偏差 > 5 分 Then 质检中心产生 alert 并关联原批改记录 |
| AC-08 | Given agent-gateway 超时 30 秒 When 批改请求发出 Then 任务进入待处理队列、自动重试 2 次，仍失败则提示并支持 mock 兜底（标注演示数据） |
| AC-09 | Given 学生查看错题本 When 点击"生成变式练习" Then 基于该知识点生成 ≥ 3 道变式题 |
| AC-10 | Given 任何角色访问平台 When 打开任意菜单 Then 左侧菜单高亮、右侧"背后逻辑"面板内容随菜单切换，无 JS 报错 |

## 8. 不做什么 + 风险与依赖

### 8.1 本期不做

- 不做在线直播/录播课程（仅资源库静态管理）。
- 不做家长端 App（学情报告一期只导出 PDF）。
- 不做手写识别 OCR 批改（学生提交为文本输入/图片附件，一期不解析图片内容）。
- 不做多校联考/区级平台（单校部署）。
- 不做自动出卷 AI 组卷（仅手动组卷 + 变式练习生成）。

### 8.2 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| LLM 批改主观题稳定性 | 评分波动引发教师不信任 | rubric 写定 + 置信度分层 + 人工复核 + 改判回流迭代 |
| 教师抵触 AI 批改 | 平台使用率低 | 先上客观题确定性批改建立信任，主观题双评过渡 |
| 学生作业数据合规 | 未成年人信息保护 | 单校私有化部署，数据不出校；访问审计留痕 |
| 依赖 agent-gateway 可用性 | 批改中断 | R-10 降级策略 + mock 兜底 |
