# 第 6 章 Agent 系统工程实践 · 导读 ★

> 让智能体工作流在真实世界的复杂考验中稳健运行，并具备持续进化能力。

## 本章要点

- Agent 系统的质量 = 设计 × 数据 × 评估 × 运维，四者缺一不可。
- 「能跑通 demo」与「能上线」之间隔着评估集、人工复核、成本控制与回滚机制。
- 能力增强的两条主线：**工具使用**（扩展行动空间）与**持续学习**（扩展知识与偏好）。

## 设计原则清单（上线前自查）

- [ ] 简单优先：能用一个提示词解决的，不上多智能体
- [ ] 每一步都有可验证的输出契约（结构化输出 / JSON Schema）
- [ ] 关键决策可回溯：完整日志（输入、提示词、工具调用、输出）
- [ ] 失败有兜底：重试次数、超时、降级话术、转人工路径
- [ ] 写操作需人工确认（邮件、订单、CRM 修改等）
- [ ] 成本可预估：单任务 token 预算与告警
- [ ] 权限最小化：工具与知识库按需授权

## Agent 评估与优化 Checklist

| 阶段 | 动作 | 配套资源 |
| --- | --- | --- |
| 上线前 | 建评估集（含正例、边界例、应拒答例） | [eval-dataset-template.jsonl](../../templates/eval-dataset-template.jsonl) |
| 上线前 | 定义指标：任务成功率、引用准确率、人工接管率 | 见下表 |
| 灰度期 | 人工复核高价值/高风险输出 | [human-review-checklist.md](../../templates/human-review-checklist.md) |
| 运行期 | 每周回归：用评估集跑全量，对比基线 | — |
| 优化期 | 失败归因 → 修提示词/检索/工具 → 再回归 | — |

### 常用评估指标速查

| 指标 | 含义 | 健康参考 |
| --- | --- | --- |
| 任务成功率 | 端到端完成且验收通过的比例 | 核心场景 ≥ 90% |
| 引用准确率 | RAG 回答中引用与结论一致的比例 | ≥ 95% |
| 幻觉率 | 无依据断言的比例 | 高风险场景趋近 0 |
| 人工接管率 | 转人工会话占比 | 逐月下降且满意度不降 |
| 单次成本 / 时延 | token 费用与端到端耗时 | 纳入预算告警 |

## 常见挑战与解决方案速查

| 挑战 | 典型症状 | 解法方向 |
| --- | --- | --- |
| 循环失控 | Agent 反复调用同一工具 | 最大步数 + 重复检测 + 人工检查点 |
| 错误累积 | 多步任务越跑越偏 | 步间校验 + 关键步人工确认 |
| 提示词漂移 | 改一处坏一片 | 提示词版本管理 + 评估集回归 |
| 检索噪声 | RAG 答案答非所问 | 元数据过滤 + rerank + 拒答策略 |
| 成本爆炸 | 长会话 token 飙升 | 上下文压缩 + 模型分级（简单任务用小模型） |

## 动手练习

1. 用评估集模板为你手头的 Agent 建 20 条评估数据（含 5 条「应拒答」）。
2. 把第 4 章 `evaluator_optimizer.py` 的评估标准换成你的业务量规，观察迭代次数与质量的关系。
