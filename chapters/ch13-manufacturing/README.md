# 第 13 章 传统制造业转型 · 导读 ★

> 私有化 Agent 平台 + 三大场景：企业数据问答、文档批量生成、数据分析看板。

## 本章要点

- 制造业的硬约束：**数据不出厂/不出域** → 私有化部署是前提而非选项（对应 13.1.3）。
- 先治理数据再谈智能：知识库质量决定问答上限。
- 从「辅助人」做起（问答、起草、看板），不急于让 AI 直接控制生产环节。

## 私有化平台搭建要点（对应 13.1.3）

- **平台选型**：优先支持私有化与内网模型接入的平台（Dify / FastGPT，见 [../ch07-agent-platforms/](../ch07-agent-platforms/)）。
- **基础设施**：内网模型服务（开源模型 + GPU 或国产算力）、向量库、对象存储、统一身份认证。
- **治理先行**：文档分级分类（部门 × 密级）、操作日志、审计与回滚机制。

## 方案卡一：企业个性化数据问答

| 环节 | 内容 |
| --- | --- |
| 痛点 | 制度、工艺、设备手册分散，员工查找难；老师傅经验未沉淀 |
| 方案 | 文档治理入库 → 带权限过滤的 RAG 问答助手 → 按部门/角色个性化 → 答案引用可追溯 |
| 权限管理 | 元数据过滤（department × confidentiality_level），越权问题统一话术不泄露存在性 |
| 提示词要点 | [../../prompts/05-knowledge-rag.md](../../prompts/05-knowledge-rag.md) 模板 2（带权限过滤） |
| 评估指标 | 检索命中率、引用准确率、越权拦截正确率 |
| 模板 | [manufacturing-rag-agent.yaml](../../templates/manufacturing-rag-agent.yaml)、[rag-workflow.yaml](../../templates/rag-workflow.yaml) |

## 方案卡二：企业文档批量生成

| 环节 | 内容 |
| --- | --- |
| 痛点 | 报告、标书、SOP 等文档重复劳动多，格式规范要求高 |
| 方案 | 模板库 + 工作流写作（资料检索 → 大纲 → 分节生成 → 格式校验）→ 协同编辑与版本管理平台沉淀终稿 |
| 关键设计 | 格式规范做成校验节点而非只靠提示词；版本管理留痕可回溯 |
| 评估指标 | 文档一次通过率、人工编辑幅度、单篇耗时对比 |
| 模板 | [../../templates/workflow-spec.yaml](../../templates/workflow-spec.yaml)（改写为文档生成流程） |

## 方案卡三：数据分析与定制看板

| 环节 | 内容 |
| --- | --- |
| 痛点 | 生产/质量/设备数据分散在各系统，报表制作依赖 IT |
| 方案 | 数据收集与处理（对接 MES/ERP 导出）→ 指标口径统一 → 统计看板快速搭建 → 自然语言问数入口 |
| 关键设计 | 指标口径字典先行；AI 负责「取数与初解读」，结论由业务负责人确认 |
| 评估指标 | 报表交付周期、口径一致性质疑次数 |

## 实施路线图

1. 平台私有化部署 + 单部门知识库问答试点（4~6 周）。
2. 扩展到文档生成场景，接入协同编辑平台。
3. 打通数据源，上线看板与问数。
4. 全程保留人工确认；生产控制类场景不在本阶段范围内。
