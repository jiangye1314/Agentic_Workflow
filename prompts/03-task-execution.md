# 框架三：任务执行提示词

> 结构：**目标 → 步骤 → 每步产出 → 输出契约**。适合多步骤、有明确交付物的任务。

## 模板 1：分步执行

```text
【目标】
{{最终要达成什么，例如：把一篇产品更新日志改写成 3 个渠道的推广文案。}}

【执行步骤】
1. {{步骤1，例如：阅读更新日志，提取 3~5 个核心卖点}}
2. {{步骤2，例如：为每个卖点匹配目标渠道（公众号/微博/社群）}}
3. {{步骤3，例如：按各渠道风格各写一条文案}}
4. {{步骤4，例如：自查每条文案是否包含行动号召（CTA）}}

【输出契约】
按以下 JSON 输出：
{
  "selling_points": ["..."],
  "drafts": [{"channel": "...", "content": "...", "has_cta": true}]
}
```

## 模板 2：带质量门槛的执行（生成→自检→改写）

```text
完成任务后，先按以下清单自检，不通过则改写后再输出：
- [ ] {{检查项1，例如：字数在要求范围内}}
- [ ] {{检查项2，例如：未使用禁用词表中的词}}
- [ ] {{检查项3，例如：数据均来自给定材料，未编造}}
自检不通过超过 {{N}} 次，输出当前最佳版本并标注「需人工复核」。
```

## 注意事项

- 步骤数量控制在 3~7 步；更多步骤考虑拆成工作流的多个节点。
- 「输出契约」尽量结构化（JSON/Markdown 表格），方便程序校验。
- 自检清单是可执行的评估器雏形，与第 6 章的评估方法衔接。
