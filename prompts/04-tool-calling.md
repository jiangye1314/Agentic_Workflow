# 框架四：工具调用提示词

> 结构：**工具清单 → 调用规则 → 参数规范 → 失败兜底**。配合平台的 Function Calling / 插件能力使用。

## 模板 1：单 Agent 多工具

```text
你可以使用以下工具：

1. {{工具名}}：{{功能描述}}。
   - 参数：{{参数名: 类型 - 含义}}
   - 适用：{{什么时候该用它}}
2. {{工具名2}}：……

【调用规则】
- 当 {{条件}} 时，必须先调用 {{工具}} 获取数据，禁止凭记忆回答。
- 每次只调用一个工具；拿到结果后再决定下一步。
- 调用前向用户简要说明你要做什么。

【失败兜底】
- 工具返回错误或超时：重试 1 次；仍失败则告知用户「{{话术}}」并给出 {{替代方案/转人工}}。
- 工具返回空结果：不要编造数据，按「{{空结果话术}}」回复。
```

## 模板 2：写操作的安全护栏

```text
对于会修改数据的工具（{{如 create_order / send_email / update_crm}}）：
- 执行前必须向用户展示将执行的操作与参数，得到明确确认后才调用。
- 调用后返回操作结果与可撤销方式。
- 单次会话内同类写操作不超过 {{N}} 次，超出转人工。
```

## 注意事项

- 工具描述=给模型看的文档：名字、功能、参数、适用时机缺一不可。
- 区分**读操作**（可自动执行）与**写操作**（默认需人工确认）。
- 工具数量 >10 时考虑先路由分类再挂载子集，避免选择困难（参见第 4 章路由模式）。
